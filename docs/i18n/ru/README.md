# Freehold Mail

**Хватит арендовать свой почтовый ящик.** Полноценный самостоятельно размещаемый почтовый стек —
почтовый сервер на Rust и современный веб-клиент.

> *Freehold*: собственность, которой вы владеете безусловно, без арендодателя и без договора аренды,
> который нужно продлевать. Именно в этом разница между тем, чтобы запустить это у себя, и тем,
> чтобы арендовать почтовый ящик у того, чья бизнес-модель — ваши данные.

Почтовый сервер, веб-почта и терминация TLS — соединённые вместе, с установщиком, который
генерирует ваши секреты и точно указывает, какие DNS-записи нужно задать. SSO подключается
опционально: есть, когда он вам нужен, и отсутствует, когда нет.

> **Статус: pre-1.0.** Редакция по умолчанию протестирована сквозным образом — реальное сообщение
> проходит путь SMTP → почтовый ящик → IMAP. Редакция с SSO запускается, её база данных и OIDC
> discovery проверены, но поставляемая версия Keycloak и вход через браузер — нет. Прочитайте
> [Известные пробелы](../../../CHANGELOG.md#known-gaps-do-not-publish-without-deciding-these),
> прежде чем полагаться на это.

## Зачем это нужно

Самостоятельное размещение почты обычно означает либо выходные, потраченные на склеивание Postfix,
Dovecot, Rspamd и веб-почты, — либо хостинговый почтовый ящик, где ваши метаданные читает кто-то
другой. Freehold Mail — третий вариант: один репозиторий, который собирает современный
безопасный по памяти стек, запускаемый вами самими, на машине, которую вы контролируете.

**Что это такое:** оркестрация. Compose-файлы, конфигурация nginx, установщик и честная
документация. **Чем это не является:** это не форк и не переписывание чьего-либо почтового сервера.

## Две редакции

| Редакция | Что входит | Вход | Проверено E2E |
|---------|----------|-------|------------|
| **Full Mail** (по умолчанию) | почтовый сервер + веб-почта + nginx | собственные имя пользователя и пароль | ✅ да |
| **Mail + SSO** | всё вышеперечисленное **+ Keycloak + PostgreSQL** | OIDC/SSO | ⚠️ частично — стек запускается, база данных и OIDC discovery проверены на Keycloak 24; поставляемая конфигурация 26.0 и полный цикл входа через браузер пока не измерены. См. [Известные пробелы](../../../CHANGELOG.md#known-gaps-do-not-publish-without-deciding-these) |

Вы вообще не касаетесь Keycloak, если вам не нужен SSO; он вынесен в необязательный overlay-файл.

## Быстрый старт

Требования: Linux-хост с Docker и Compose v2, домен под вашим контролем, доступные порты
25/465/587/993/80/443 и TLS-сертификат.

```bash
git clone https://github.com/Novaza-ai/freeholdmail && cd freeholdmail
./install.sh
```

> **Только что арендовали сервер или собираетесь?** Сначала прочитайте
> [`docs/HOSTING.md`](../../../docs/HOSTING.md). Этот документ ведёт от голого VPS до работающего
> почтового ящика, с командой проверки на каждом шаге, и называет ту единственную вещь, которую
> потом уже не исправить: **большинство дешёвых провайдеров блокируют исходящий порт 25**, из-за
> чего почта становится невозможной, как бы хорошо вы всё ни настроили. Там же приведены измеренные
> значения RAM, CPU и диска, чтобы вы арендовали подходящий размер, а не гадали.

Установщик спрашивает вашу редакцию и домен, затем:

1. генерирует стойкие случайные секреты в `.env` (режим 600, `umask 077` — ничего не захардкожено);
2. фиксирует образы контейнеров по дайджесту;
3. разрешает пути Let's Encrypt (символические ссылки `live/` не работают внутри контейнеров);
4. поднимает стек и выводит команды для создания вашего первого почтового ящика.

Затем создайте почтовый ящик и войдите по адресу `https://<your-domain>`:

```bash
# domain, then user — the roles field is required, or SMTP AUTH refuses the account
curl -u admin:$STALWART_FALLBACK_ADMIN_SECRET -X POST http://127.0.0.1:8080/api/principal \
  -H 'Content-Type: application/json' -d '{"type":"domain","name":"example.com"}'

curl -u admin:$STALWART_FALLBACK_ADMIN_SECRET -X POST http://127.0.0.1:8080/api/principal \
  -H 'Content-Type: application/json' \
  -d '{"type":"individual","name":"you@example.com","secrets":["<password>"],
       "emails":["you@example.com"],"roles":["user"]}'
```

Наконец, задайте DNS-записи — MX, SPF, DKIM и DMARC описаны в
[`docs/DNS.md`](../../../docs/DNS.md).

## Архитектура

```
Browser ─HTTPS─▶ nginx ─┬─ /  and  /api/*  ─▶ Bulwark webmail (FE)   :3000
                        ├─ /jmap, /.well-known/jmap ─▶ Stalwart  :8080/JMAP
                        └─ /.well-known/openid-configuration ─▶ Keycloak (SSO edition)
SMTP/IMAP clients ───────────────────────────────▶ Stalwart  :25 :465 :587 :993
```

`/api/*` принадлежит веб-почте, которая обслуживает там собственные маршруты конфигурации и сессий.
До почтового сервера доходят только `/jmap` и JMAP discovery; его административный API намеренно
не открыт через прокси.

Каждый блок — независимый, заменяемый контейнер. Связь фронтенда с бэкендом — **только сетевая**:
JMAP поверх HTTP, без связывания кода. Именно эта граница позволяет данному репозиторию быть под
MIT, тогда как каждый компонент сохраняет собственную лицензию.

## Сравнение с аналогами

| | Freehold Mail | Mailu / Mailcow | docker-mailserver | Google Workspace |
|---|---|---|---|---|
| Почтовый сервер | Stalwart (Rust, нативный JMAP) | Postfix + Dovecot | Postfix + Dovecot | — |
| Веб-почта в комплекте | ✅ | ✅ | ❌ (своя) | ✅ |
| JMAP | ✅ | ❌ | ❌ | ❌ |
| SSO/OIDC | ✅ опциональная редакция | частично | ❌ | ✅ |
| Данные остаются у вас | ✅ | ✅ | ✅ | ❌ |
| Зрелость | **pre-1.0** | зрелый | зрелый | коммерческий |

Mailu, Mailcow и docker-mailserver превосходны и куда лучше обкатаны в бою. Выбирайте
Freehold Mail, если вам нужен именно нативный для JMAP почтовый сервер на Rust вместе с веб-почтой
и опциональным SSO в одном месте.

## Честно о рамках проекта

**Сейчас:** почтовые ящики, SMTP/IMAP/JMAP, веб-почта, TLS, опциональный SSO — полноценная замена
хостинговому почтовому ящику.

**Пока нет:** маркетинговые/массовые рассылки, новостные письма, общие командные ящики, тикет-системы,
инструменты миграции от других провайдеров и управляемая панель администрирования. Массовая рассылка,
в частности, — это дисциплина доставляемости, а не переключатель функции; не рассчитывайте на неё.

**Дорожная карта:** см. [`ROADMAP.md`](../../../ROADMAP.md) — в ближайшей перспективе это надёжность
(SSO, проверенный на поставляемом Keycloak; актуальная апстрим-линейка почтового сервера;
доставляемость, измеренная на реальном домене). В более далёкой перспективе мы хотим, чтобы этот стек
стал тем, которым программные агенты смогут пользоваться безопасно: MCP-сервер поверх JMAP и
ограниченные по области, отзываемые учётные данные для каждого агента вместо того, чтобы отдавать боту
свой пароль. Ничего из этого пока не построено, и проект намеренно не назван в честь этого.
**Вклад в работу над агентами приветствуется — см. «Help wanted» в дорожной карте.**

## Безопасность

Открытая ретрансляция (open relay) запрещена, отправка почты требует аутентификации, а парольные
механизмы (`PLAIN`/`LOGIN`) предлагаются только после STARTTLS — всё это измерено, а не принято на
веру. Есть и реальные слабые места, которые нужно заранее учитывать, в том числе апстримный
административный API, возвращающий пароли учётных записей в открытом виде. **Прочитайте
[`SECURITY.md`](../../../SECURITY.md), прежде чем открывать это в интернет.**

## Тесты и эксплуатация

И то и другое есть в репозитории — вы можете сами воспроизвести любое утверждение выше:

```bash
tests/test_config.sh      # static: both editions validate, no secrets, digests pinned … (~seconds)
tests/test_e2e.sh         # real: stack up → send a message → read it back over IMAP (~2 min)
tests/test_e2e.sh --sso   # same, plus Keycloak + PostgreSQL
```

`test_e2e.sh` собирает одноразовый стек на портах, доступных только через loopback, с собственными
томами и именами контейнеров, и разбирает его при завершении — он не помешает работающему
развёртыванию. См. [`tests/README.md`](../../../tests/README.md), включая то, что эти тесты
намеренно **не** покрывают.

Повседневная эксплуатация — резервные копии, обновление сертификатов, управление почтовыми ящиками,
обновления, сценарии реагирования на инциденты — описана в
[`docs/RUNBOOK.md`](../../../docs/RUNBOOK.md). Предварительные требования — в
[`docs/REQUIREMENTS.md`](../../../docs/REQUIREMENTS.md).
