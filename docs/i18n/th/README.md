# Freehold Mail

**เลิกเช่ากล่องจดหมายของคุณเสียที** เมลสแตกแบบ self-hosted ที่ครบถ้วน — เมลเซิร์ฟเวอร์เขียนด้วย Rust
และเว็บไคลเอนต์สมัยใหม่

> *Freehold* (กรรมสิทธิ์ขาด): ทรัพย์สินที่คุณเป็นเจ้าของโดยสมบูรณ์ ไม่มีเจ้าของที่ดิน และไม่มีสัญญาเช่าให้ต้องต่ออายุ
> นั่นคือความแตกต่างระหว่างการรันสิ่งนี้ด้วยตัวเอง กับการเช่ากล่องจดหมายจากคนที่มีโมเดลธุรกิจ
> คือข้อมูลของคุณ

สร้าง secret ให้คุณ และบอกอย่างชัดเจนว่าต้องตั้งเรคคอร์ด DNS ใดบ้าง SSO เป็นทางเลือก
มีให้เมื่อคุณต้องการ และไม่มีอยู่เลยเมื่อคุณไม่ต้องการ

> **สถานะ: pre-1.0** รุ่นค่าเริ่มต้นผ่านการทดสอบแบบ end to end แล้ว — ข้อความจริงเดินทางผ่าน
> SMTP → กล่องจดหมาย → IMAP ส่วนรุ่น SSO นั้นเริ่มทำงานได้ และฐานข้อมูลกับ OIDC discovery
> ผ่านการตรวจสอบแล้ว แต่เวอร์ชัน Keycloak ที่แถมมาและโฟลว์การเข้าสู่ระบบผ่านเบราว์เซอร์ยังไม่ผ่านการตรวจสอบ
> โปรดอ่าน [ช่องว่างที่ทราบแล้ว](../../../CHANGELOG.md#known-gaps-do-not-publish-without-deciding-these)
> ก่อนที่จะพึ่งพาสิ่งนี้

## ทำไมจึงมีโครงการนี้

โดยทั่วไปการโฮสต์อีเมลด้วยตัวเองมักจบลงที่การใช้เวลาทั้งสุดสัปดาห์ประกอบ Postfix, Dovecot,
Rspamd และเว็บเมลเข้าด้วยกัน — หรือไม่ก็ใช้กล่องจดหมายแบบโฮสต์ที่มีคนอื่นอ่านเมตาดาต้าของคุณ
Freehold Mail คือทางเลือกที่สาม: รีโพเดียวที่ประกอบสแตกสมัยใหม่ให้คุณรันเอง บนเครื่องที่คุณควบคุม
เมลเซิร์ฟเวอร์และเว็บเมลเขียนด้วยภาษาที่ปลอดภัยด้านหน่วยความจำ ส่วน nginx และ PostgreSQL เขียนด้วย C
ดังนั้น "ปลอดภัยด้านหน่วยความจำ" อธิบายเฉพาะส่วนที่เราเลือก ไม่ใช่ทั้งสแตก

**สิ่งที่มันเป็น:** orchestration ไฟล์ Compose, การตั้งค่า nginx, ตัวติดตั้ง และเอกสารที่ตรงไปตรงมา
**สิ่งที่มันไม่ใช่:** ไม่ใช่ fork หรือการเขียนใหม่ของเมลเซิร์ฟเวอร์ของใคร

## สองรุ่น

| รุ่น | ประกอบด้วย | การเข้าสู่ระบบ | ทดสอบ E2E แล้ว |
|---------|----------|-------|------------|
| **Full Mail** (ค่าเริ่มต้น) | เมลเซิร์ฟเวอร์ + เว็บเมล + nginx | ชื่อผู้ใช้/รหัสผ่านแบบเนทีฟ | ✅ ใช่ |
| **Mail + SSO** | ทั้งหมดข้างต้น **+ Keycloak + PostgreSQL** | OIDC/SSO | ⚠️ บางส่วน — สแตกเริ่มทำงานได้ ฐานข้อมูลและ OIDC discovery ผ่านการตรวจสอบบน Keycloak 24 ส่วนการตั้งค่า 26.0 ที่แถมมาและรอบการเข้าสู่ระบบผ่านเบราว์เซอร์ยังไม่ได้วัดผล ดู [ช่องว่างที่ทราบแล้ว](../../../CHANGELOG.md#known-gaps-do-not-publish-without-deciding-these) |

คุณจะไม่ต้องแตะ Keycloak เลยเว้นแต่คุณต้องการ SSO เพราะมันอยู่ในไฟล์ overlay ที่เป็นทางเลือก

## เริ่มต้นอย่างรวดเร็ว

สิ่งที่ต้องมี: โฮสต์ Linux ที่มี Docker และ Compose v2, โดเมนที่คุณควบคุม, พอร์ต
25/465/587/993/80/443 ที่เข้าถึงได้ และใบรับรอง TLS

```bash
git clone https://github.com/Novaza-ai/freeholdmail && cd freeholdmail
./install.sh
```

> **เพิ่งเช่าเซิร์ฟเวอร์ หรือกำลังจะเช่า?** อ่าน [`docs/HOSTING.md`](../../../docs/HOSTING.md) ก่อน
> เอกสารนี้พาคุณจาก VPS เปล่า ๆ ไปจนถึงกล่องจดหมายที่ใช้งานได้จริง พร้อมคำสั่งตรวจสอบในทุกขั้นตอน
> และระบุชัดถึงสิ่งเดียวที่คุณแก้ไขทีหลังไม่ได้: **ผู้ให้บริการราคาถูกส่วนใหญ่บล็อกพอร์ต 25 ขาออก**
> ซึ่งทำให้การส่งอีเมลเป็นไปไม่ได้ ไม่ว่าคุณจะตั้งค่าสิ่งนี้ได้ดีเพียงใด อีกทั้งยังมีตัวเลข RAM, CPU
> และดิสก์ที่วัดมาจริง เพื่อให้คุณเช่าขนาดที่เหมาะสมแทนการเดา

ตัวติดตั้งจะถามถึงรุ่นและโดเมนของคุณ จากนั้น:

1. สร้าง secret แบบสุ่มที่แข็งแรงลงใน `.env` (โหมด 600, `umask 077` — ไม่มีการ hardcode ใด ๆ);
2. ปักหมุดอิมเมจคอนเทนเนอร์ด้วย digest;
3. แก้ค่าเส้นทาง Let's Encrypt ของคุณ (symlink `live/` ใช้งานไม่ได้ภายในคอนเทนเนอร์);
4. นำสแตกขึ้นทำงาน และพิมพ์คำสั่งสำหรับสร้างกล่องจดหมายแรกของคุณ

จากนั้นสร้างกล่องจดหมายและเข้าสู่ระบบที่ `https://<your-domain>`:

```bash
# domain, then user — the roles field is required, or SMTP AUTH refuses the account
curl -u admin:$STALWART_FALLBACK_ADMIN_SECRET -X POST http://127.0.0.1:8080/api/principal \
  -H 'Content-Type: application/json' -d '{"type":"domain","name":"example.com"}'

curl -u admin:$STALWART_FALLBACK_ADMIN_SECRET -X POST http://127.0.0.1:8080/api/principal \
  -H 'Content-Type: application/json' \
  -d '{"type":"individual","name":"you@example.com","secrets":["<password>"],
       "emails":["you@example.com"],"roles":["user"]}'
```

สุดท้ายให้ตั้งเรคคอร์ด DNS ของคุณ — [`docs/DNS.md`](../../../docs/DNS.md) มีทั้ง MX, SPF, DKIM และ DMARC

## สถาปัตยกรรม

```
Browser ─HTTPS─▶ nginx ─┬─ /  and  /api/*  ─▶ Bulwark webmail (FE)   :3000
                        ├─ /jmap, /.well-known/jmap ─▶ Stalwart  :8080/JMAP
                        └─ /.well-known/openid-configuration ─▶ Keycloak (SSO edition)
SMTP/IMAP clients ───────────────────────────────▶ Stalwart  :25 :465 :587 :993
```

`/api/*` เป็นของเว็บเมล ซึ่งให้บริการเส้นทางการตั้งค่าและเซสชันของตัวเองที่นั่น
มีเพียง `/jmap` และ JMAP discovery เท่านั้นที่ไปถึงเมลเซิร์ฟเวอร์ ส่วน admin API ของมันถูกจงใจ
ไม่เปิดเผยผ่านพร็อกซี

ทุกกล่องคือคอนเทนเนอร์อิสระที่สลับเปลี่ยนได้ ระหว่างฟรอนต์เอนด์กับแบ็กเอนด์เชื่อมกันด้วย**เครือข่ายเท่านั้น** —
JMAP บน HTTP ไม่มีการลิงก์โค้ดเข้าด้วยกัน ขอบเขตนี้เองที่ทำให้รีโพนี้เป็น MIT ได้
ในขณะที่แต่ละคอมโพเนนต์ยังคงสัญญาอนุญาตของตัวเองไว้

## ขอบเขต แบบตรงไปตรงมา

**ตอนนี้:** กล่องจดหมาย, SMTP/IMAP/JMAP, เว็บเมล, TLS, SSO ที่เป็นทางเลือก — เป็นตัวแทน
ที่น่าเชื่อถือของกล่องจดหมายแบบโฮสต์

**ยังไม่ใช่ตอนนี้:** อีเมลการตลาด/ส่งจำนวนมาก, จดหมายข่าว, กล่องจดหมายรวมของทีม, ระบบ ticket,
เครื่องมือย้ายข้อมูลจากผู้ให้บริการอื่น หรือแผงควบคุมแบบ managed โดยเฉพาะการส่งจำนวนมากนั้น
เป็นวินัยด้าน deliverability ไม่ใช่สวิตช์เปิดปิดฟีเจอร์ — อย่าสันนิษฐานว่าทำได้

**โรดแมป:** ดู [`ROADMAP.md`](../../../ROADMAP.md) — ระยะใกล้คือความน่าเชื่อถือ (SSO ที่ตรวจสอบแล้วบน
Keycloak ที่แถมมา, สายเวอร์ชันเมลเซิร์ฟเวอร์ต้นน้ำปัจจุบัน, deliverability ที่วัดผลบนโดเมนจริง)
ไกลออกไป เราต้องการให้สแตกนี้เป็นสแตกที่
ซอฟต์แวร์เอเจนต์ใช้งานได้อย่างปลอดภัย: เซิร์ฟเวอร์ MCP บน JMAP และข้อมูลรับรองต่อเอเจนต์
ที่จำกัดขอบเขตและเพิกถอนได้ แทนที่จะยื่นรหัสผ่านของคุณให้บอต ทั้งหมดนี้ยังไม่ได้สร้างขึ้น และ
โครงการนี้ก็จงใจไม่ตั้งชื่อตามสิ่งนั้น **เรายินดีรับการมีส่วนร่วมในงานด้านเอเจนต์ —
ดู "Help wanted" ในโรดแมป**

## การทดสอบและการปฏิบัติงาน

ทั้งสองอย่างอยู่ในรีโพ — คุณสามารถทำซ้ำทุกข้ออ้างข้างต้นด้วยตัวเองได้:

```bash
tests/test_config.sh      # static: both editions validate, no secrets, digests pinned … (~seconds)
tests/test_e2e.sh         # real: stack up → send a message → read it back over IMAP (~2 min)
tests/test_e2e.sh --sso   # same, plus Keycloak + PostgreSQL
```

`test_e2e.sh` สร้างสแตกแบบใช้แล้วทิ้งบนพอร์ตที่ผูกกับ loopback เท่านั้น โดยมีโวลุ่มและ
ชื่อคอนเทนเนอร์ของตัวเอง และรื้อทิ้งเมื่อจบการทำงาน — มันจะไม่รบกวนดีพลอยเมนต์ที่กำลังทำงานอยู่
